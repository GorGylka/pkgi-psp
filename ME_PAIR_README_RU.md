# PKGi PSP — CPU + ME, прототип парной расшифровки v1

Целевая проверка: PSP-3000, ARK 5.0.0 Built Apr 21.
Собрано PSPDEV v20261001 / psp-gcc 15.2.0. На физической PSP автор этой сборки её не запускал.

## Быстрая проверка — компилировать не требуется

1. Сохрани рабочий EBOOT.PBP (версия примерно 1450 КБ/с) отдельно.
2. Скопируй bin/me/EBOOT.PBP из архива в /PSP/GAME/PKGI/EBOOT.PBP на PSP.
3. Остальные файлы уже установленного PKGi — FONT.OTF, LANG, конфигурацию и базы — оставь на месте.
4. Установи тот же небольшой PKG в обычном режиме PSP/GAME (EBOOT/PBP). ISO/CSO этим прототипом не ускоряются.
5. Посмотри /PSP/GAME/PKGI/pkgi-me-log.txt. Строка ME_ENABLED: 1 означает, что ME прошёл четыре сравнения с CPU и используется. При отказе запуска/самопроверки включается CPU. Ошибка ME после начала установки останавливает установку; повреждённый текущий выходной файл удаляется.
6. Запиши время/скорость стадии Installing, проверь запуск игры и сохрани лог ДО следующей установки: каждая попытка перезаписывает его.
7. Для сравнения скопируй bin/cpu/EBOOT.PBP на то же место. Это контрольная CPU-сборка с тем же новым циклом чтения/записи и без ME-библиотеки. Она не создаёт новый ME-лог: старый лог от ME-сборки не является её результатом.

Для первого опыта не используй сон во время установки и выходи через Circle. Системный HOME уже был проблемным в предыдущей версии; здесь он отдельно не исправлялся.

## Что изменено

- Два последовательных блока по 256 КиБ. ME получает второй блок, затем CPU расшифровывает первый; после ожидания результата ME оба блока записываются в исходном порядке.
- AES-ключи разворачиваются заранее, отдельный контекст для CPU и ME. Файловые операции, UI и выделение памяти выполняются только на CPU.
- Контрольная структура некэшируемая и выровнена по 64 байтам; данные передаются с writeback/invalidate и барьерами. Для первой версии используется отдельный статический буфер ME с копированием туда и обратно. Это упрощает владение памятью, но имеет цену по производительности.
- Последний короткий блок, в том числе неполные 16 байт, обрабатывается корректно. Короткие read/write повторяются до полного результата; ошибки не считаются успехом.
- Самопроверка ME: 16, 31, 4096 и 262144 байт, разные смещения и переполнение счётчика. Проверяется совпадение AES-CTR с CPU.
- Ожидание ME ограничено по времени. При тайм-ауте вызывается kernel bridge, удерживающий ME в reset; текущая установка завершается ошибкой. Автоматического повторного XOR над частично обработанными данными нет.
- После установки worker останавливается. Мост библиотеки загружается один раз за запуск приложения; следующая установка перезапускает worker через тот же мост.
- Обычный suspend блокируется на время владения ME через scePowerLock; разблокируется после остановки. Системные медиа-кодеки одновременно с пользовательским worker не используются.

Предыдущие изменения HTTP: sceHttp для http://, кэш скачивания 8 МиБ, резерв вне C-кучи 4 МиБ, без SHA-256 загрузки и докачки — сохранены. Эти 8 МиБ не являются размером блоков установки.

## Зависимость ME

mcidclan, PSP Media Engine Custom Core (MIT):
https://github.com/mcidclan/psp-media-engine-custom-core
Зафиксирован коммит 0197c99ea581d728188af30ccfd9bb5f7afe6280.
Исходники и LICENSE.md находятся в source/pkgi-psp/vendor/me-core.

Библиотека извлекает встроенный kcall.prx рядом с EBOOT при первом запуске ME. Не удаляй его во время работы PKGi. Это экспериментальный kernel bridge; успешная компиляция и тесты на ПК не подтверждают совместимость его операций с конкретной PSP/CFW. Самопроверки не могут защитить от всех возможных зависаний на этапе запуска ядра ME.

## Сборка исходников в Ubuntu / WSL

Распакуй source/pkgi-psp в отдельную папку, например ~/projects/pkgi-me-pair1.
Используй уже установленный PSPDEV; переменные PSPDEV и PATH должны быть настроены.

```bash
cd ~/projects/pkgi-me-pair1
sudo apt install -y xxd
make -C vendor/dbglogger -f Makefile.psp install
sh scripts/build-me-lib.sh
psp-cmake -S . -B build-me -DCMAKE_BUILD_TYPE=Release -DPKGI_ENABLE_ME=ON
cmake --build build-me --parallel 2
```

Результат: build-me/EBOOT.PBP. Для контрольной сборки:

```bash
psp-cmake -S . -B build-cpu -DCMAKE_BUILD_TYPE=Release -DPKGI_ENABLE_ME=OFF
cmake --build build-cpu --parallel 2
```

По умолчанию опция ME выключена. Вариант OFF не требует me-core.

## Что прислать после теста

- Полный pkgi-me-log.txt от ME-сборки.
- Скорость и, по возможности, полное время Installing одного и того же PKG на ME и контрольной CPU-сборках.
- Успешно ли установилось, запускается ли игра.
- Проходит ли повторная установка без перезапуска PKGi.

Показание скорости в интерфейсе остаётся приблизительным; сравнение полного времени полезнее. Ускорение не обещается: копирование, синхронизация, частота ME и карта памяти могут съесть выигрыш. Сначала нужно подтвердить корректный запуск ME на устройстве.
